# Receipt follow-through development run, v7

This follow-up retains the original three v6 outcomes as reported and is separate from the pilot. All attempted runs, including calibration failures and unfinished orders, are retained. The completion criterion is a fresh server delivery chest containing at least one of every one of the twelve specified products in a single fresh episode.

The starting schedule is two mixed-library seed 711 episodes, prompt-only then enforced. Both run the same cached Qwen/MLX snapshot, same sampler, prompt, tools, focused queue, fresh stock, 17×17 boxes and Minecraft 1.21.6 world. Each episode has 70 calls, a 200,000 observed-token turn-start threshold, 240 primitive attempts, 18 fresh test opportunities and a one-hour active limit. A completed receipt for an unchanged revision is reused and logged as a cache hit, with no new test kit allocated. Before episode scoring the planner sees the actual target, live chest and stock, the exact procedure and receipt, and its latest tool result. A deterministic queue chooses the first undelivered target. Qwen chooses each verify, use, edit, direct action and finish; the operator does not choose tools or edit a live run.

If a method fails reproduction, a recipe-book helper may offer a single vanilla crafting or smelting step that could produce a missing ingredient for the observed failed step. Suggestions use the actual test inventory, the failed procedure, installed vanilla recipes and no clean-library oracle. Explicit Qwen selection is required to insert a suggestion. A new method identity requires its own test. These are tooling-assisted development runs, not evidence of unaided repair ability. Smelt inputs/vanilla mappings and fuel availability are checked before initial transfer; recover_furnace retrieves abandoned ingredients via normal Minecraft operations.

Before runs: live positive reproduction of all twelve clean procedures and test of production chest delivery, idempotent receipt read, four negative controls of original faulty procedures without repair, insufficient input precheck and recovery of one deliberately stranded raw iron. After runs: reconcile server-backed deliveries, receipts, revisions, test material allocation, model usage, and source identity. Stop on 12/12 per arm. At most one additional separately frozen repair/retry per incomplete arm following a concrete diagnosis (four total agent episodes). No replacement runs or changes during active episodes. A preflight-only snapshot missing an import was retained and never executed.
